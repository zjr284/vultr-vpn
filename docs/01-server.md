# 01 · 选机器与开防火墙

## 1. 选哪家

| 厂商 | 优点 | 缺点 |
|---|---|---|
| **Vultr** | 按小时计费、机房多、销毁重建方便 | 中国方向线路一般（Cogent / NTT） |
| **DigitalOcean** | 稳定、文档全 | 略贵，亚洲机房少 |
| **BandwagonHost（搬瓦工）** | 有 CN2 GIA 优化线路 | 贵、库存少 |
| **阿里云国际 / 腾讯云国际** | 国内访问快 | 需要实名、支付麻烦 |

本文以 **Vultr** 为例（$5/月，按小时结算，随时销毁）。

## 2. 选哪个机房

从北京/上海出发的大致体验：

| 机房 | 延迟 | 说明 |
|---|---|---|
| 东京 `nrt` | 80~180ms | 首选，延迟低、带宽足 |
| 首尔 `icn` | 150~250ms | 走 Telia 时反而更差 |
| 洛杉矶 `lax` | 150~250ms | 带宽大，延迟高 |
| 新加坡 `sgp` | 80~150ms | 华南用户更友好 |

> 延迟主要取决于**回程线路**，不是物理距离。同一机房不同 IP 段体验可能完全不同。

## 3. 套餐

`Cloud Compute → Shared CPU → vc2-1c-1gb`：

- 1 vCPU / 1GB RAM / 25GB SSD / 1TB 流量
- $5/月（≈¥36），按小时约 $0.007

跑本方案绰绰有余（实测内存占用 < 200MB）。

## 4. 系统

**Ubuntu 24.04 LTS x64**（22.04 也可以）。脚本用 `apt`，不支持 CentOS / Debian 之外的分支。

## 5. SSH Key

部署时选择已有的 SSH key，不要用密码登录：

```bash
# 本机没有 key 的话先生成
ssh-keygen -t ed25519 -C "vpn"

# 把 ~/.ssh/id_ed25519.pub 的内容贴到 Vultr → Account → SSH Keys
```

## 6. 防火墙（关键步骤）

Vultr 的防火墙是**独立资源**，要在 `Firewalls` 里建一个组，然后挂到实例上。

必开端口：

| 协议 | 端口 | 用途 |
|---|---|---|
| tcp | 22 | SSH |
| tcp | 80 | ACME 证书 + 订阅 |
| tcp | 443 | Xray Reality |
| tcp | 8443 | 订阅 HTTPS（可选） |
| udp | 443 | Hysteria2 |
| udp | 51821 | WireGuard |

建议把 SSH 限制成你自己的 IP（`x.x.x.x/32`），其余对所有 IP 开放。

> ⚠️ **规则生效有 1~3 分钟延迟。** 改完立刻测大概率还是不通，等两分钟再试——我们就因为没等，误判过一次"服务器坏了"。

## 7. 部署前先测一下 IP

新开的机器，先用手机/电脑直接访问：

```bash
curl -m 10 http://<IP>/
```

如果连 TCP 握手都不给（而不是 404/拒绝），说明这个 IP 在中国方向被黑洞了 —— **直接销毁重开**，别浪费时间排查。

这类 IP 的特征是：`ping` 不通、任意端口都超时，但从服务器自己往外访问一切正常。
